# M4.3 Remaining trade heads: eval report and release gate

Status: in-progress. Slice 1 (eval report + gate) built and tested 2026-11-20. Training on real data waits on verified samples.

## Scope
Trade heads for `structural`, `hvac`, `electrical`, `plumbing_fp` reuse the M4.2 pipeline unchanged: one ordinal classifier per trade ladder (`fauxel_cv/ladders.py`), dataset from human-verified samples (`fauxel_cv.dataset`), training + temperature calibration + ONNX export (`fauxel_cv.train`), loaded by the API model slot. What M4.3 adds is the **per-trade eval report**, its definition of done.

## Eval (`python -m fauxel_cv.evaluate`)
- Scores the exported `model.onnx` with the model slot's preprocessing (cv2 INTER_AREA, RGB, /255, mean/std) and the manifest temperature, so the report measures what production runs, not the torch model.
- Split: capture-held-out `val` by default (`--split test` when a dedicated test split exists). Never frame-level holdout.
- Per trade: accuracy, within one rung, macro F1, per-rung P/R/F1, confusion matrix, ECE, NLL, state-level (5-state enum) accuracy, percent MAE.
- Auto-accept block: coverage and precision of predictions with confidence ≥ 0.8. Those write verified status without a human, so this is the number that matters for write-back.
- Outputs `<models>/<trade>/eval.json` and `<models>/EVAL_REPORT.md` (all trades; `no_model` / `no_data` rows keep gaps visible).
- `--strict` exits 1 if any trade fails the gate or has no held-out data.

## Release gate (defaults, `GATE` in `evaluate.py`)
| Check | Threshold |
|---|---|
| Held-out samples | n ≥ 50 (`--min-n`) |
| Auto-accept precision (conf ≥ 0.8) | ≥ 95% |
| ECE | ≤ 0.10 |
| Within one rung | ≥ 90% |

## Run
```
python -m fauxel_cv.dataset --api $FAUXEL_API --key $FAUXEL_KEY --project <pid> --out data/
for t in structural hvac electrical plumbing_fp; do python -m fauxel_cv.train --data data --trade $t --out models; done
python -m fauxel_cv.evaluate --models models --data data --strict
```

## Tests
`services/cv-inference/tests/test_evaluate.py` (handcrafted ONNX, runs in seconds): clean model passes, 30% label noise fails the auto-accept gate and `--strict`, missing split reports `no_data`. The slow e2e test also checks that ONNX eval accuracy matches the trainer's torch val accuracy.
